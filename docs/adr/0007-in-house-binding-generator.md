# 0007. In-house binding generator, with committed output

- Status: Accepted
- Date: 2026-10-05

## Context

Jade calls three C libraries (Dawn, SDL3, miniaudio) on every target, including NativeAOT, iOS AOT
and Mono WebAssembly. The interop must follow strict rules (see
[0008](0008-two-layer-interop.md) and [0009](0009-interop-mapping-conventions.md)) and expose an
idiomatic C# API. Hand-written bindings drift from the headers; third-party binding libraries
impose their own mapping choices and release cadence.

Verified on 2026-10-05 with SDK `11.0.100-rc.1.26425.128`: a file-based app can pull in other
files with `#:include` without any preview flag, and the CA2266 analyzer warns when a file-based
entry point does not start with a `#!` line.

## Decision

- All interop code is generated by our own generator. No hand-written bindings and no
  third-party binding library.
- The generator is a .NET file-based app: `scripts/binding-generator.cs`, split into files under
  `scripts/binding-generator/` and composed with `#:include`. Like every file-based entry point in
  `scripts/`, it starts with a `#!` line.
- Inputs:
  - WebGPU: `dawn.json` from the pinned Dawn commit;
  - SDL3 and miniaudio: their C headers, parsed with libclang through ClangSharp, used only as a
    parser;
  - a per-library annotation configuration that adds what the sources cannot express (ownership,
    nullability, array lengths, callbacks, functions safe for `SuppressGCTransition`, and so on);
  - `native/versions.json` for the pinned versions.
- Output goes to `Generated/*.g.cs` in each interop project, next to the hand-written partials and
  the generator configuration of that library.
- Generated code is committed. CI regenerates the bindings and fails if `git diff` is not empty.
- The generator is deterministic: same inputs, byte-identical output on every machine (stable
  ordering, no timestamps, no absolute paths, fixed line endings).

## Consequences

- We control every mapping rule and can evolve the API without waiting on a third party.
- We own the generator's maintenance, including following changes in `dawn.json` and in the C
  headers.
- Reviewers see the effect of a generator change or a dependency update as a diff of generated
  code.
- CI needs libclang and the pinned headers to regenerate SDL3 and miniaudio bindings.
- The intermediate representation and the detailed mapping rules are still open (see the
  roadmap).

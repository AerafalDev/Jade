# 0009. Interop mapping conventions

- Status: Accepted
- Date: 2026-10-05

## Context

The generator needs fixed rules for mapping C constructs to C#. They must hold on every target,
including 32-bit WebAssembly, and keep the raw layer blittable (see
[0008](0008-two-layer-interop.md)). This record lists the rules already decided; the generator's
intermediate representation and the remaining mapping rules are still open.

## Decision

### Declarations

- `[assembly: DisableRuntimeMarshalling]`.
- Functions use `[LibraryImport]` with
  `[UnmanagedCallConv(CallConvs = [typeof(CallConvCdecl)])]` and strictly blittable signatures.
- `[SuppressGCTransition]` only on functions marked as such in the generator configuration
  (short, non-blocking, no callback).

### Types

- C `long` / `unsigned long` map to `CLong` / `CULong`.
- `size_t` maps to `nuint`, never `long` or `ulong`.
- `WGPUBool` maps to a dedicated 4-byte type; C `bool` (1 byte) maps to `bool`.
- Fixed-size C arrays map to `[InlineArray(N)]` structs, never `fixed` buffers.
- C unions map to `LayoutKind.Explicit` structs with every field at offset 0. No other explicit
  offset is used anywhere. C# union types do not replace C unions.
- `WGPUStringView` maps to `ReadOnlySpan<byte>`; null and empty strings stay distinct (the
  `WGPU_STRLEN` sentinel).

### Handles, structs and descriptors

- Handles are `readonly partial struct` wrappers over `nint`, implementing `IEquatable<T>` and the
  equality operators.
- Shared behaviours (`AddRef`/`Release`, the `sType` of chained structs) are expressed through
  interfaces with static abstract members, so generic helpers work without boxing.
- Chained output structs, whose `nextInChain` is filled in by the caller, are passed by `ref`,
  never `out`.
- Descriptors have a parameterless constructor that applies the schema's default values, and
  `required` members for values without a default. Code never relies on `default(T)` for a
  descriptor.

### Callbacks and asynchrony

- Callbacks use `delegate* unmanaged[Cdecl]` function pointers and generated
  `[UnmanagedCallersOnly]` trampolines (static, non-generic), with a `GCHandle` in the userdata.
  Managed delegates are never marshalled.
- Asynchronous WebGPU operations are exposed as `Task`. On native targets, `ProcessEvents` is
  called regularly so that callbacks are delivered.

### Names and generated files

- The generator handles identifiers that start with a digit and the casing of acronyms.
- Generated files are named `*.g.cs`, start with `// <auto-generated/>`, carry
  `[GeneratedCode]`, and declare every type `partial`.
- `.gitattributes` marks `*.g.cs` as `linguist-generated=true`.

### Verification

- The layout of every struct is checked by generated tests comparing C `sizeof`/`offsetof` with the
  C# layout, on every target, WebAssembly included.

## Consequences

- The same generated code is correct on 64-bit and 32-bit targets because pointer-sized and
  `long`-sized types use `nint`/`nuint`/`CLong`/`CULong`.
- Layout tests need a small C program or library per target, built by the native toolchain.
- Rules not listed here are decided with the generator's design and recorded in a new ADR.
